#  Setup K8-Cluster using kubeadm [K8 Version-->1.28.1]

### 1. Update System Packages [On Master & Worker Node]

```bash
sudo apt-get update
```

### 2. Install Docker[On Master & Worker Node]

```bash
sudo apt install docker.io -y
sudo chmod 666 /var/run/docker.sock
```

### 3. Install Required Dependencies for Kubernetes[On Master & Worker Node]

```bash
sudo apt-get install -y apt-transport-https ca-certificates curl gnupg
sudo mkdir -p -m 755 /etc/apt/keyrings
```

### 4. Add Kubernetes Repository and GPG Key[On Master & Worker Node]

```bash
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.28/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.28/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
```

### 5. Update Package List[On Master & Worker Node]

```bash
sudo apt update
```

### 6. Install Kubernetes Components[On Master & Worker Node]

```bash
sudo apt install -y kubeadm=1.28.1-1.1 kubelet=1.28.1-1.1 kubectl=1.28.1-1.1
```

### 7. Initialize Kubernetes Master Node [On MasterNode]

```bash
sudo kubeadm init --pod-network-cidr=172.31.0.0/16
```

### 8. Configure Kubernetes Cluster [On MasterNode]

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### 9. Deploy Networking Solution (Calico) [On MasterNode]

```bash
kubectl apply -f https://docs.projectcalico.org/manifests/calico.yaml
```

### 10. Deploy Ingress Controller (NGINX) [On MasterNode]

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v0.49.0/deploy/static/provider/baremetal/deploy.yaml
```

- **`Service "kube-dns" is invalid: spec.clusterIPs: Invalid value: []string{"10.96.0.10"}: failed to allocate IP 10.96.0.10: provided IP is already allocated`**
  - Kubernetes tried to create the `kube-dns` Service (used by CoreDNS).
  - The default ClusterIP (`10.96.0.10`) was already in use, likely from a previous failed or partial cluster initialization.
  - This usually happens if you ran `kubeadm init` before and didn’t fully reset the cluster.

- **`The connection to the server 172.31.24.186:6443 was refused`**
  - The API server isn’t running or reachable.
  - This is expected if `kubeadm init` failed partway through.

---

## 🛠️ How to Fix

1. **Reset kubeadm state**
   ```bash
   sudo kubeadm reset
   ```
   - This cleans up any partially created cluster resources.

2. **Clean up CNI and kubelet state**
   ```bash
   sudo systemctl stop kubelet
   sudo systemctl stop docker   # or containerd, depending on runtime
   sudo rm -rf /var/lib/cni/
   sudo rm -rf /var/lib/kubelet/*
   sudo rm -rf /etc/cni/net.d
   sudo systemctl start docker
   sudo systemctl start kubelet
   ```

3. **Re-run kubeadm init**
   ```bash
   sudo kubeadm init --pod-network-cidr=10.244.0.0/16
   ```
   - This should now allocate a fresh Service IP for CoreDNS.

4. **If you want a different cluster DNS IP**
   - You can override the default with:
     ```bash
     sudo kubeadm init --pod-network-cidr=10.244.0.0/16 --service-cidr=10.96.0.0/12
     ```
   - Or pick another range if `10.96.0.10` is conflicting with something else.

---

## ✅ Key Takeaway
- The error means CoreDNS couldn’t get its default Service IP because it was already allocated from a previous attempt.  
- Run `kubeadm reset` and clean up kubelet/CNI state before re-initializing.  
- After a clean reset, `kubeadm init` should succeed and create the DNS service properly.
